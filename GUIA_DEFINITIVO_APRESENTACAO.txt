============================================================
GUIA DEFINITIVO DE INSTALAÇÃO E APRESENTAÇÃO - LEARNHUB
Expo Go + Node.js + Express + MySQL + Cloudflare Tunnel
============================================================

Este guia explica como executar o LearnHub em outro computador,
inclusive quando o celular estiver usando dados móveis e o computador
estiver conectado a outra rede.


============================================================
1. COMO O SISTEMA FUNCIONA
============================================================

Cadastro e login seguem este caminho:

Expo Go no celular
        -> requisição HTTP
API Node.js/Express no computador
        -> consulta SQL
MySQL no computador

Quando celular e computador estão em redes diferentes:

Expo Go
        -> túnel do Expo
Metro no computador

Aplicativo
        -> Cloudflare Tunnel
API Express no computador
        -> conexão local
MySQL no computador

O Cloudflare publica somente a API Express. O MySQL não deve ser
publicado diretamente na internet.


============================================================
2. PROGRAMAS NECESSÁRIOS
============================================================

- Node.js 22.13 ou superior;
- npm;
- MySQL Server ou MariaDB;
- Expo Go no celular;
- cloudflared.exe, se celular e computador estiverem em redes diferentes;
- acesso à internet para instalar dependências e criar os túneis.

Confirme o Node.js:

node --version
npm --version


============================================================
3. PREPARAR O PROJETO EM UM COMPUTADOR NOVO
============================================================

Abra o CMD e entre na pasta do projeto:

cd /d C:\CAMINHO\PARA\LearnHub

Exemplo:

cd /d C:\Users\rafae\AppLearnHub\LearnHub

Instale todas as dependências:

npm install

O projeto utiliza npm workspaces. Um único npm install prepara o
aplicativo Expo e o backend.


============================================================
4. CONFIGURAR O MYSQL
============================================================

Confirme se existe um serviço MySQL:

sc query type= service state= all | findstr /I mysql

O nome normalmente é MySQL80. Para iniciar:

net start MySQL80

Se o serviço tiver outro nome, use o nome mostrado pelo primeiro
comando.

Teste o acesso ao MySQL:

mysql -u root -p -h localhost -P 3306

Digite a senha definida na instalação. Para sair:

exit;


============================================================
5. CONFIGURAR BACKEND/.ENV
============================================================

Na raiz do projeto:

copy backend\.env.example backend\.env
notepad backend\.env

Configure:

PORT=3000

DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD="SUA_SENHA_DO_MYSQL"
DB_NAME=learnhub

JWT_SECRET=uma-frase-aleatoria-com-mais-de-32-caracteres
CORS_ORIGIN=*

Se o usuário root não tiver senha:

DB_PASSWORD=

Se a senha tiver #, espaços ou caracteres especiais, use aspas:

DB_PASSWORD="Minha#Senha@123"

Não coloque espaços antes ou depois do sinal de igual.

Correto:

DB_PASSWORD="MinhaSenha"

Incorreto:

DB_PASSWORD = "MinhaSenha"


============================================================
6. CRIAR O BANCO LEARNHUB
============================================================

No CMD, a partir da raiz do projeto:

mysql -u root -p < database\database.sql

Digite a senha do MySQL.

O arquivo cria automaticamente:

- banco learnhub;
- tabela usuarios;
- e-mail único;
- perfis colaborador e diretor;
- campo de senha para hash bcrypt;
- data de criação.

Se o comando mysql não for reconhecido, use o MySQL Workbench:

1. Abra o Workbench;
2. conecte-se ao MySQL;
3. abra database\database.sql;
4. execute todo o arquivo pelo ícone de raio.

Também é possível usar o caminho completo:

"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p < database\database.sql

Para conferir:

mysql -u root -p

SHOW DATABASES;
USE learnhub;
SHOW TABLES;
DESCRIBE usuarios;
exit;


============================================================
7. TESTAR O BACKEND LOCALMENTE
============================================================

Abra o primeiro CMD:

cd /d C:\CAMINHO\PARA\LearnHub
npm run backend

O resultado correto é:

Banco de dados conectado com sucesso.
API INICIADA COM SUCESSO
Porta: 3000
Banco de dados: CONECTADO

Não feche esse CMD.

Abra no navegador do computador:

http://localhost:3000/api/health

Resposta esperada:

{"success":true,"api":"online","database":"connected"}

Não prossiga enquanto o health local não estiver funcionando.

Diagnóstico completo:

npm run diagnose


============================================================
8. USO NA MESMA REDE LOCAL
============================================================

Se celular e computador estiverem na mesma rede Wi-Fi, use:

npm run dev

Esse comando inicia backend e Expo juntos e mostra o QR Code.

O aplicativo detecta automaticamente o IP usado pelo Metro. Não é
necessário editar IP dentro dos arquivos do projeto.

Permita Node.js no Firewall do Windows, principalmente em redes
privadas.


============================================================
9. USO COM DADOS MÓVEIS E SEM HOTSPOT
============================================================

Se o celular estiver nos dados móveis e o computador estiver em outra
rede, eles não conseguem acessar uma API local diretamente.

Será necessário usar dois túneis:

1. Cloudflare Tunnel para a API Express;
2. túnel do Expo para o Metro.

Baixe cloudflared.exe pelo site oficial da Cloudflare e salve, por
exemplo, na pasta Downloads.


============================================================
10. CRIAR O TÚNEL DA API
============================================================

Mantenha o primeiro CMD com npm run backend aberto.

Abra o segundo CMD e vá até a pasta do cloudflared.exe:

cd /d C:\Users\SEU_USUARIO\Downloads

Execute:

cloudflared.exe tunnel --url http://localhost:3000

Será apresentada uma URL parecida com:

https://palavras-aleatorias.trycloudflare.com

Não feche esse CMD.

Os avisos abaixo normalmente não impedem o funcionamento:

Cannot determine default configuration path
Unable to determine the system root certificate pool

O importante é aparecer:

Your quick Tunnel has been created

Teste pelo navegador do celular:

https://palavras-aleatorias.trycloudflare.com/api/health

Resposta esperada:

{"success":true,"api":"online","database":"connected"}


============================================================
11. CONFIGURAR A URL PÚBLICA NO EXPO
============================================================

Na raiz do projeto:

notepad .env.local

Coloque somente a URL base recebida:

EXPO_PUBLIC_API_URL=https://palavras-aleatorias.trycloudflare.com

Regras:

- não acrescente /api;
- não acrescente /api/health;
- não coloque barra no final;
- não coloque aspas;
- não deixe espaços ao redor do sinal de igual.

Correto:

EXPO_PUBLIC_API_URL=https://palavras-aleatorias.trycloudflare.com

Incorreto:

EXPO_PUBLIC_API_URL=https://palavras-aleatorias.trycloudflare.com/api


============================================================
12. INICIAR O EXPO POR TÚNEL
============================================================

Abra o terceiro CMD:

cd /d C:\CAMINHO\PARA\LearnHub
npm run start:tunnel

Leia o QR Code com o Expo Go.

Durante a apresentação, mantenha abertos:

CMD 1: npm run backend
CMD 2: cloudflared.exe tunnel --url http://localhost:3000
CMD 3: npm run start:tunnel

Se qualquer um desses processos for encerrado, parte do sistema deixará
de funcionar.


============================================================
13. QUANDO A URL DO CLOUDFLARE MUDAR
============================================================

O Quick Tunnel é temporário. Toda vez que o cloudflared for encerrado e
aberto novamente, poderá ser criada outra URL.

Quando isso acontecer:

1. copie a nova URL;
2. abra .env.local;
3. substitua a URL antiga;
4. encerre o Expo com Ctrl+C;
5. execute npm run start:tunnel novamente;
6. leia o novo QR Code.

Não é necessário alterar código-fonte nem editar IP em vários arquivos.


============================================================
14. TESTAR CADASTRO
============================================================

No Expo Go:

1. abra Cadastre-se;
2. preencha nome e e-mail;
3. informe e confirme uma senha com pelo menos 8 caracteres;
4. escolha Colaborador ou Diretor;
5. toque em Cadastrar.

Fluxo:

Expo Go
  -> Cloudflare Tunnel
  -> API Express
  -> validação
  -> bcrypt gera o hash
  -> MySQL salva o usuário


============================================================
15. PROVAR QUE O USUÁRIO FOI SALVO
============================================================

Execute no MySQL Workbench ou terminal:

USE learnhub;

SELECT
  id,
  nome,
  email,
  tipo_usuario,
  created_at,
  CHAR_LENGTH(senha) AS tamanho_do_hash,
  LEFT(senha, 7) AS inicio_do_hash
FROM usuarios
ORDER BY id DESC;

O usuário deve aparecer e a senha deve começar de forma semelhante a:

$2b$10$

Isso comprova que a senha não foi salva em texto puro.


============================================================
16. TESTAR LOGIN
============================================================

1. volte para a tela de login;
2. informe o e-mail cadastrado;
3. informe a senha correta;
4. toque em Acessar Plataforma.

Fluxo:

Expo Go
  -> API Express
  -> busca usuário no MySQL
  -> bcrypt compara a senha
  -> API retorna token JWT
  -> aplicativo redireciona para Principal

Teste também uma senha errada. A resposta deverá ser:

E-mail ou senha incorretos.


============================================================
17. BÔNUS: MYSQL DA ESCOLA JÁ INSTALADO, MAS SENHA DESCONHECIDA
============================================================

O projeto não consegue descobrir automaticamente a senha do MySQL.
Não tente contornar a segurança ou redefinir a senha sem autorização.

PRIMEIRO TESTE: ROOT SEM SENHA

Algumas instalações de XAMPP/MariaDB utilizam root sem senha:

mysql -u root

Se entrar sem pedir senha, configure:

DB_USER=root
DB_PASSWORD=

E importe:

mysql -u root < database\database.sql


SEGUNDO TESTE: MYSQL WORKBENCH COM SENHA SALVA

Abra o MySQL Workbench. Pode existir uma conexão já configurada e com a
senha salva no Windows.

Se o Workbench conectar:

1. execute database\database.sql;
2. peça ao professor ou administrador para criar um usuário exclusivo
   para o aplicativo.

O administrador pode executar:

CREATE USER IF NOT EXISTS 'learnhub_app'@'localhost'
IDENTIFIED BY 'LearnHub@Escola2026';

GRANT SELECT, INSERT, UPDATE, DELETE
ON learnhub.*
TO 'learnhub_app'@'localhost';

FLUSH PRIVILEGES;

Depois configure backend\.env:

DB_HOST=localhost
DB_PORT=3306
DB_USER=learnhub_app
DB_PASSWORD="LearnHub@Escola2026"
DB_NAME=learnhub

Esse procedimento é mais seguro do que usar a conta root.


SE NÃO HOUVER SENHA NEM CONEXÃO SALVA

Será necessário pedir ao professor ou administrador uma destas opções:

- fornecer uma conta temporária do MySQL;
- importar database\database.sql;
- criar o usuário learnhub_app;
- autorizar outra instância de MySQL/MariaDB.

Mensagem sugerida ao responsável:

"Preciso importar um banco chamado learnhub e conectar uma API Node.js
local. Pode criar um usuário MySQL chamado learnhub_app com permissão no
banco learnhub ou fornecer uma conta temporária?"

Sem uma conta válida não é possível acessar aquele servidor MySQL,
mesmo que ele já esteja instalado.


============================================================
18. ERROS MAIS COMUNS
============================================================

ER_ACCESS_DENIED_ERROR

Causa: usuário ou senha incorretos.

Confira DB_USER e DB_PASSWORD em backend\.env e teste:

mysql -u root -p


ER_BAD_DB_ERROR

Causa: banco learnhub não existe.

Execute:

mysql -u root -p < database\database.sql


ECONNREFUSED NA PORTA 3306

Causa: serviço MySQL parado.

Execute, usando o nome correto do serviço:

net start MySQL80


CLOUDFLARE RETORNA 502 BAD GATEWAY

Causa: backend não está respondendo em localhost:3000.

Teste:

http://localhost:3000/api/health

Depois reinicie:

npm run backend


EXPO ABRE, MAS CADASTRO NÃO CONECTA

Confira:

1. a URL pública ainda está ativa?
2. o health público abre no celular?
3. .env.local contém a URL atual?
4. o Expo foi reiniciado depois da alteração?
5. backend e cloudflared continuam abertos?


NETWORK REQUEST FAILED

Teste primeiro no celular:

https://URL-ATUAL.trycloudflare.com/api/health

Se não abrir, o problema está no backend ou no túnel, não nas telas do
aplicativo.


============================================================
19. ENCERRAR A APRESENTAÇÃO
============================================================

Pressione Ctrl+C nos três CMDs:

- Expo;
- backend;
- Cloudflare Tunnel.

O MySQL pode continuar funcionando como serviço do Windows.

O Quick Tunnel é temporário e deve ser usado apenas para demonstração e
testes.
